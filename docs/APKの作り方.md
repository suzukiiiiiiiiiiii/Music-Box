# APK の作り方（はじめての人向け）

GitHub に置いたソースから、スマホに入れられる APK を作るまでの手順。
パソコンに Flutter や Android Studio を入れる必要はない。全部 GitHub の
サーバー側でビルドされる。

ブラウザだけで完結する。スマホのブラウザでもできる。

---

## 用語のたな卸し

先に3つだけ。ここが分かると迷わない。

| 言葉 | 意味 |
| --- | --- |
| **リポジトリ** | ソースコードの置き場所。今回は `suzukiiiiiiiiiiii/Music-Box` |
| **ブランチ** | 作業用の枝分かれ。本流が `main` |
| **Actions** | GitHub が用意しているビルド係。push すると自動で動く |
| **Artifacts（成果物）** | Actions が作ったファイルの置き場。ここから APK を取る |

ビルドの流れはこれだけ:

```
ソースを push  →  Actions が動く  →  Artifacts に APK が置かれる  →  ダウンロード
```

---

## 手順1: 最初の1回だけ ─ PR を main に取り込む

**なぜ必要か。** 今の `main` には `music-box.zip` しか入っていない。アプリの
ソースとビルド設定は PR のブランチ側にある。取り込まないと `main` を push しても
何も作られない。

1. ブラウザで https://github.com/suzukiiiiiiiiiiii/Music-Box/pull/1 を開く

2. ページの下のほうに緑や灰色のボタンが並んでいる。
   **「Ready for review」** という灰色のボタンを押す。
   - このボタンは PR が「下書き（Draft）」状態のときだけ出る
   - 下書きのままだとマージできないので、必ず先に押す
   - 押すと PR の見出しの「Draft」バッジが消える

3. **「Merge pull request」** という緑のボタンを押す

4. 確認画面になるので **「Confirm merge」** を押す

5. 「Pull request successfully merged and closed」と出たら成功。
   下に **「Delete branch」** ボタンが出るが、押しても押さなくてもよい
   （押すと作業用の枝が消えるだけで、`main` の中身は無事）

これで `main` にアプリ一式が入り、**同時にビルドが自動で始まる**。
手順2へ進む。

---

## 手順2: ビルドの様子を見る

1. リポジトリのトップ https://github.com/suzukiiiiiiiiiiii/Music-Box を開く

2. 上のほうのタブから **「Actions」** を押す

3. 一覧のいちばん上が、いま動いている実行。左のアイコンで状態が分かる。

   | アイコン | 意味 |
   | --- | --- |
   | 🟡 黄色いぐるぐる | 実行中。待つ |
   | ✅ 緑のチェック | 成功。APK が出来ている |
   | ❌ 赤いバツ | 失敗。手順5を見る |

4. 名前の部分（「Build APK」など）を押すと詳細が開く

5. 左側の **「build」** を押すと、何をしているか1行ずつ流れる。
   見なくてもよいが、止まっているのか動いているのか確かめたいときに便利

**かかる時間**: 初回は Flutter と Gradle のダウンロードが入るので **8〜12分**。
2回目以降はキャッシュが効くので短くなる。
気長に待つ。ページを閉じても裏で進む。

---

## 手順3: APK をダウンロードする

1. 緑のチェックが付いたら、その実行の詳細ページを開く
   （Actions タブ → 一覧のいちばん上をクリック）

2. ページを **いちばん下までスクロール** する

3. **「Artifacts」** という枠がある。その中の **`music-box-apk`** を押す

4. `music-box-apk.zip` がダウンロードされる

5. zip を解凍すると **`app-release.apk`** が出てくる。これが本体

**注意点**

- GitHub の仕様で、APK 単体ではなく **必ず zip に包まれて** ダウンロードされる。
  解凍がひと手間だが避けられない
- Artifacts は **90日で自動的に消える**。手元に残したいなら保存しておく
- ファイルサイズは 26MB 前後

---

## 手順4: スマホに入れる

### 4-1. APK をスマホに移す

どれか1つでよい。

- **スマホのブラウザで直接ダウンロードする**（いちばん楽）
  スマホで GitHub にログインして、手順3をそのままスマホ上でやる
- USB ケーブルでパソコンとつないでコピーする
- Google ドライブや自分宛てのメールに添付して送る

### 4-2. zip を解凍する

Android 13 以降なら標準の「ファイル」アプリで zip をタップすれば解凍できる。
古い機種なら「ZArchiver」などの解凍アプリを入れる。

### 4-3. インストールする

1. 解凍して出てきた `app-release.apk` をタップ

2. 「セキュリティ上の理由から、この提供元のアプリはインストールできません」
   のような警告が出る。これは正常。Play ストア以外のアプリは既定で
   ブロックされているだけ

3. 警告の中の **「設定」** を押す

4. **「この提供元のアプリを許可」** をオンにする
   （機種によって「不明なアプリのインストール」「提供元不明のアプリ」など名前が違う）

5. 戻ってもう一度 APK をタップ → **「インストール」**

6. ホーム画面に「Music Box」が出れば完了

### 4-4. 初回に必要なこと

1. アプリを開くと曲が0件の状態から始まる
2. **「フォルダを選ぶ」** を押す
3. 音楽ファイルの読み取り許可を求められるので **許可** する
4. 音楽が入っているフォルダを選ぶ
5. スキャンが走って一覧に並ぶ

`/storage/emulated/0/Music`、`/Download`、`/Podcasts` は指定しなくても毎回見に行く。

## 手順5: これから自分で変更して APK を作り直す

手順1が終わっていれば、あとは **push するだけで毎回自動でビルドされる**。

### 方法A: ブラウザだけで直す（おすすめ）

パソコンに何も入れなくてよい。

1. リポジトリで直したいファイルを開く
   （例: 色を変えたいなら `lib/settings_model.dart`）

2. ファイルの右上にある **鉛筆アイコン（✏️ Edit this file）** を押す

3. その場で文字を書き換える

4. ページ右上の **「Commit changes...」** という緑のボタンを押す

5. ダイアログが出る。
   - 上の欄に、何を変えたかを短く書く（例: `アクセント色をふやす`）
   - **「Commit directly to the main branch」** が選ばれていることを確認
   - **「Commit changes」** を押す

6. これで push 完了。**自動でビルドが始まる**。手順2へ

### 方法B: パソコンで git を使う

git が使える人向け。まとめて何ファイルも直すときはこちら。

```bash
# 1. 最初の1回だけ: 手元にコピーを持ってくる
git clone https://github.com/suzukiiiiiiiiiiii/Music-Box.git
cd Music-Box

# 2. ファイルを好きなエディタで編集する

# 3. 変更を記録して送る
git add -A
git commit -m "何を変えたかを書く"
git push origin main
```

push した瞬間にビルドが始まる。手順2へ。

2回目以降、作業を始める前には `git pull origin main` で最新を取ってくる。

### 方法C: 何も変えずにビルドだけやり直す

「さっきのビルドが失敗したのでもう一度」というときはこれ。

1. **Actions** タブを開く
2. 左のリストから **「Build APK」** を押す
3. 右側に **「Run workflow」** というボタンが出るので押す
4. ブランチが `main` になっているのを確認して、もう一度 **「Run workflow」**

## 手順6: ビルドが失敗したとき（赤いバツ）

慌てなくてよい。原因はログに書いてある。

### 失敗した場所を探す

1. Actions タブ → 赤いバツが付いた実行をクリック
2. 左の **「build」** をクリック
3. 手順が縦に並んでいる。**赤いバツが付いている行** を探してクリックすると開く
4. 開いた中の **`Error:`** や **`error:`** で始まる行が原因

### よくある失敗

**`flutter analyze` の行で止まった**

書いたコードに文法や型の間違いがある。エラー行にファイル名と行番号が出ているので
そこを直す。APK を組む前にここで止まる作りにしてあるので、待ち時間が短くて済む。

**`flutter test` の行で止まった**

動きが変わってしまい、用意してあるテストと食い違っている。
意図した変更ならテスト側（`test/` の中）も直す。

**`GeneratedPluginRegistrant.java` で `cannot find symbol`**

追加したパッケージが今の Android ビルド環境に対応していない。
そのパッケージのバージョンを上げるか下げる。詳しくは README のつまずきどころへ。

**`checkReleaseAarMetadata` で「compile against version 37 or later」**

パッケージが要求する Android SDK が、Flutter の既定より新しい。
そのパッケージのバージョンを下げる。詳しくは README のつまずきどころへ。

**赤いバツだが、直前のビルドから何も変えていない**

外部のサーバーが一時的に不調なだけのことがある。手順5の方法Cでもう一度回す。

## よくある質問

**お金はかかる？**

このリポジトリが public（公開）なら Actions は無料枠が無制限。かからない。
private（非公開）にすると月あたりの無料時間に上限が出る。

**Play ストアに出せる？**

このままでは出せない。ビルドの署名にデバッグ用の鍵が使われているため。
自分の端末に入れて使うぶんには問題ない。

**古い APK も取っておける？**

Actions タブには過去の実行が残っていて、それぞれに Artifacts が付いている。
90日以内ならいつでも取り直せる。

**間違えて main を壊してしまった**

Actions が失敗するだけで、リポジトリは壊れない。
リポジトリのトップ →「commits」から1つ前の状態を確認できる。
戻したいときは、その commit を開いて `Revert` を押す。

**ビルドが始まらない**

`main` ブランチに push したか確認する。他のブランチに push した場合、
PR を作らないとビルドは走らない。
